# infra — the-invisible-cities.com

Production runs on the shared DigitalOcean droplet described in
`~/Code/util/infra/` (OS, nginx globals, backups, restore). This directory is
everything specific to this site. Facts as of 2026-10-23.

## Where it lives

| | |
|---|---|
| Domain | `the-invisible-cities.com` (`www.` → 301 to the apex; port 80 → 301 to https) |
| Stack | Kirby 5 flat-file CMS on PHP 8.5-FPM (`/run/php/php8.5-fpm.sock`), no database |
| Site root | `/home/forge/the-invisible-cities.com/current/` → `releases/<id>/`, 4 releases kept (Forge setting) |
| Forge site id | `3311015` (appears in `forge-conf/3311015/…` and the error-log name) |
| TLS | Let's Encrypt via Forge, renewed Mon 11:01 (`/root/.letsencrypt-renew/3647249`) |
| Runs as | `forge` |

No daemons or queue workers. One scheduled job, defined in Forge's Scheduler (documented in `crontab`): a weekly
`rm -rf /mnt/data-volume/media/pages/*` that empties Kirby's generated page-media cache.

## Server layout

```
/home/forge/the-invisible-cities.com/
  .env                       VOLUME_NAME, REPO_URL, PNPM_PATH — deploy-time only (see env.example)
  current -> releases/<id>
  releases/<id>/             one git clone per deploy
    .env -> ../../.env
    media, assets/font, site/accounts            -> /mnt/data-volume/…
    site/config/config.php, site/config/.license -> /mnt/data-volume/site/config/…
    content/{1_projects,2_prints,3_journal,journal-series,travels}  -> /mnt/data-volume/content/…
    content/4_about/j_by_manu.jpg                -> /mnt/data-volume/content/4_about/…
/mnt/data-volume/            15 GB block volume, the only persistent state
```

Everything Kirby writes (orders, subscribers, journal, uploaded media, accounts) lands
on the volume through those symlinks, so the volume snapshot is the backup of record.
The real secrets (Stripe, Mailgun, `newsletter_*` keys, Kirby `.license`) are in
`/mnt/data-volume/site/config/config.php` and `.license`, not in `.env`. One release
still carries a stray `config.the-invisible-cities.ca.php -> config.php` symlink from
before the domain change; `forge_deploy.sh` no longer creates it.

## Deploy

1. Push to `master` → `.github/workflows/deploy.yml` (environment `production`) calls the
   Forge deploy-trigger URL (secret `FORGE_DEPLOY_URL`) with the commit, author and message.
2. Forge runs `forge_deploy.sh`: `$CREATE_RELEASE()` (clone into `releases/<id>`, submodules),
   strips the token from the remote URL, builds the symlinks above, `pnpm install` +
   `pnpm run prod`, then `$ACTIVATE_RELEASE()` (swap `current`, prune old releases) and
   `sudo service php8.5-fpm reload` — required, because OPcache runs with
   `validate_timestamps=0`.
3. The workflow polls the Forge API until that deployment is `finished`/`failed`, then curls
   the site.

`forge` is allowed `service php8.5-fpm reload` without a password (`util/infra/droplet.md`).

## nginx

`nginx.conf` is the site's vhost; at its two ends it includes `forge-conf/3311015/{before,after}/*`
and at the end of the server block `forge-conf/3311015/site.conf` (copied under `forge-conf/`). Shared
pieces come from `~/Code/util/infra/nginx/` (`snippets/bot-mitigation.conf`, the
`$blocked_agent` map, the `invis_api` rate-limit zone — currently commented out in the vhost).
It sets its own access log (`/var/log/nginx/access.log`); the error log is
`/var/log/nginx/3311015-error.log`, rotated by `/etc/logrotate.d/forge-3311015`.

## Leaving Forge — what needs a new owner

- **Release handling** — clone, symlinks, `current` swap, pruning old releases, the `.env` link
  into each release (Forge does that last one; the script doesn't).
- **Deploy trigger and status** — replace the curl + Forge API polling in `deploy.yml` with SSH
  as `forge` running the deploy script, and use its exit status.
- **vhost includes** — inline `forge-conf/3311015/site.conf` and the two redirect files into
  `nginx.conf`, drop the `# FORGE …` include lines.
- **TLS** — the `ssl_certificate` paths point at Forge-managed directories that change on every
  renewal (`/etc/nginx/ssl/domains/1860889/<cert-id>/`). A replacement (certbot webroot or
  acme.sh) needs to keep `/.well-known/acme-challenge/` served from `/home/forge/.letsencrypt/`
  (the vhost already does).
- **Logrotate** entry `forge-3311015`.
- **The scheduled job** in `crontab`.
